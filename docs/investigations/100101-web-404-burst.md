# 100101 — Web 404 burst / path enumeration

## What fired

Rule `100101` (level 8). Composite/frequency rule: fires when stock rule
`31101` ("web server 400 error code") matches **12 or more times within 60
seconds from the same source IP**.

## Host

- **Target:** `ubuntu-zrahman`, Apache `access.log`
- **Source IP:** `100.114.163.62`
- **Client:** `curl/8.19.0` (per User-Agent) — a scripted crawl, not a browser

## Raw log

`samples/web-100101-404-burst.log` — 19 requests, `00:46:01`–`00:46:21` (20
seconds, ~1-second spacing), every request returning `404 477`:

```
100.114.163.62 - - [04/Aug/2026:00:46:01 +0000] "GET /admin HTTP/1.1" 404 477 "-" "curl/8.19.0"
100.114.163.62 - - [04/Aug/2026:00:46:02 +0000] "GET /wp-login.php HTTP/1.1" 404 477 "-" "curl/8.19.0"
100.114.163.62 - - [04/Aug/2026:00:46:03 +0000] "GET /.env HTTP/1.1" 404 477 "-" "curl/8.19.0"
100.114.163.62 - - [04/Aug/2026:00:46:04 +0000] "GET /.git/config HTTP/1.1" 404 477 "-" "curl/8.19.0"
...
100.114.163.62 - - [04/Aug/2026:00:46:21 +0000] "GET /old/ HTTP/1.1" 404 477 "-" "curl/8.19.0"
```

Every path is distinct and drawn from a wordlist of high-value targets —
CMS login pages (`wp-login.php`, `wp-admin`, `admin/login`), source/secret
leakage paths (`.env`, `.git/config`, `.aws/credentials`, `.ssh/id_rsa`),
backup/dump artifacts (`backup.sql`, `dump.sql`, `robots.txt.bak`), and an
API path (`api/v1/users`). This is textbook directory/path enumeration, not
a coincidental run of 404s from a broken link or crawler.

19 matches in 20 seconds clears the 12/60s threshold comfortably.

## Severity assessment

**Level 8 is appropriate.** Per the alert scale, 6–9 is "Suspicious, worth a
look," with "odd user-agent" as a worked example — this event is a step
above that (it's a *pattern* of 19 targeted probes, not a single odd
request), but correctly stops short of the 10–12 "would page someone" band.
Justification:

- Every single request in this burst 404'd — nothing was found, nothing was
  exposed. The activity indicates reconnaissance intent but zero confirmed
  impact, which is exactly what the "suspicious, worth a look" tier is for.
- If any of these paths had returned `200` instead of `404` (e.g. an
  actually-exposed `.env` or `.git/config`), that would be a materially
  different, much more severe event — an information-disclosure
  confirmation, not just a scan — and would warrant a separate,
  higher-severity rule rather than folding it into this one's threshold
  logic.
- The rule is intentionally generic (any stock `31101` match counts, not
  just sensitive-looking paths), so its level has to reflect the average
  case (path enumeration / broken crawler) rather than the worst case
  (successful info disclosure). Level 8 is the right average.

No changes recommended.
